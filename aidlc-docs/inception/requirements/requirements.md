## 意図分析

| 項目         | 内容 |
|--------------|------|
| ユーザー要求 | 子供向けのアプリを作成する |
| 要求種別     | 新規プロジェクト |
| スコープ     | 単一の学習体験を提供する単一 Web アプリ |
| 複雑度       | 中程度。幼児向けの使いやすさと安全性を重視する |

## プロダクト概要

3〜5歳の未就学児が、保護者のアカウントや個人情報を必要とせずに、文字・数・言語のいずれか 1 つの学習体験を楽しく繰り返せる Web アプリを作成する。

初回リリースでは、最小限の学習体験を安全に検証する。広告、外部リンク、子供の行動追跡、オンライン交流、クラウドへの進捗保存は提供しない。

## 機能要件

### FR-01: 単一の学習体験

アプリは、3〜5歳が一人でも取り組める、文字・数・言語のいずれか 1 つに焦点を当てた短い学習体験を提供する。

### FR-02: 年齢に適した操作

子供が画面上の大きく明確な操作要素を使い、学習活動を開始、回答、完了できるようにする。複雑な入力、長い説明文、読字能力を前提とする操作は必要としない。

### FR-03: 即時で肯定的なフィードバック

回答または操作の後に、子供が次の行動を理解できる短く肯定的なフィードバックを表示または再生する。不正解時にも否定的、威圧的、恐怖を与える表現を使用しない。

### FR-04: 繰り返し利用

学習体験を終了した子供が、個人情報の登録やログインなしに最初から再び遊べるようにする。

### FR-05: 子供だけで完結する体験

初回リリースでは、保護者向けダッシュボード、利用時間管理、複数プロフィール、承認機能を提供しない。

### FR-06: ローカル完結

個人情報、ニックネーム、進捗、利用履歴を保存または送信しない。学習コンテンツと画面操作はブラウザー内で完結させる。

## 安全性とプライバシー要件

### SR-01: 広告と外部遷移の禁止

広告、課金誘導、外部リンク、SNS 共有、第三者コンテンツへの遷移を表示しない。

### SR-02: 年齢適合性

すべての文言、画像、音、操作、フィードバックは 3〜5歳に適した内容とする。恐怖、不安、暴力、不適切な広告表現、子供を誘導する表現を含めない。

### SR-03: Security Baseline の適用

Security Baseline をブロッキング制約として適用する。Web アプリでは少なくとも HTTP セキュリティヘッダー、依存関係の固定と脆弱性確認、安全なエラー処理、コンテンツの安全な取り扱いを実装・検証する。

### SR-04: 将来の拡張に対する保護

個人情報の収集、アカウント、オンライン機能、保存機能を将来追加する場合は、保護者同意、アクセス制御、入力検証、暗号化を要件として再評価する。

## 利便性とアクセシビリティ要件

### AR-01: 視認性と操作性

年齢に適した文字サイズ、十分な色のコントラスト、大きなタップまたはクリック領域を使用する。色だけに依存して意味や正誤を伝えない。

### AR-02: 音声に依存しない利用

音声を使用する場合でも、視覚的な手掛かりと操作方法を提供する。音量調整または音なしでの利用を妨げない。

### AR-03: 予測可能な画面遷移

画面遷移とボタンの動作を一貫させ、突然の全画面遷移、ポップアップ、外部サイトへの移動を発生させない。

## 品質とテスト要件

### QR-01: 基本動作の検証

学習開始、回答、フィードバック、最初からの再開を例示ベースの自動テストで検証する。

### QR-02: Property-Based Testing の適用

Property-Based Testing をブロッキング制約として適用する。学習問題、採点、コンテンツ状態、またはデータ変換にテスト可能な性質がある場合、性質を設計で特定し、PBT と例示ベースのテストを作成する。

### QR-03: PBT の再現性

PBT は失敗時に縮小された再現ケースとシードを出力できるフレームワークで実行し、継続的インテグレーションで実行する。

### QR-04: 対応ブラウザー

現行のデスクトップおよびモバイル Web ブラウザーで、主要な学習体験を利用できるようにする。具体的な対応範囲は技術設計で確定する。

## 成功基準

| 優先度 | 基準 |
|--------|------|
| 最優先 | 子供が学習体験を楽しく繰り返し利用できる |
| 次点   | 学習または習慣に関する成果を測定できる設計へ拡張可能である |
| 次点   | 早期に試作品を公開し、フィードバックを得られる |

初回リリースでは、最優先基準を、子供が迷わずに開始・回答・再開できることと、繰り返し学習できることによって評価する。計測データを収集しないため、初期のフィードバックは保護者または観察者から任意に得る方法を後続計画で検討する。

## 制約と対象外

* 初回リリースは Web アプリとする
* 初回リリースは 1 つの学習体験に限定する
* アカウント、ログイン、プロフィール、進捗保存を提供しない
* 広告、外部リンク、課金、SNS、チャット、オンライン交流を提供しない
* 実在する専門家による教育・安全性レビューは初回リリースの必須条件にしない

## 拡張ルールの準拠状況

| 拡張                    | 状態      | 要件分析での扱い |
|-------------------------|-----------|------------------|
| Security Baseline       | 準拠      | SR-03 と SR-04 にセキュリティ要件を定義した。インフラ、認証、永続データ、API は未設計または対象外であり、該当ルールは後続設計で評価する |
| Property-Based Testing  | 準拠      | QR-02 と QR-03 に PBT の設計、実装、CI 要件を定義した。具体的な性質と対象コンポーネントは機能設計で特定する |
